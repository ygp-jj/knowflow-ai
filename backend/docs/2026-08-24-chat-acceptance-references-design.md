## 2. 引用折叠/展开（前端）

### 2.1 交互

| 项 | 约定 |
|----|------|
| 默认状态 | **收起**；展示「引用 (N)」与「展开」 |
| 展开后 | 展示每条引用的完整正文（`content` / `content_preview`）及元信息（chunk / 文档 / score） |
| 出现时机 | 仅当本轮流式 **`done` 之后**再渲染引用区；流式过程中（`token` 阶段）不展示引用 |
| 历史消息 | 从 `messages/list` 加载的助手消息：有引用时同样默认收起，可展开 |
| 无引用 | 不展示引用区 |

### 2.2 实现要点

- 主要改动：`frontend/src/views/ChatPage.vue`
- 每条助手消息维护本地展开状态（如 `refsExpanded`）；切换会话时随消息列表重置
- 流式：`onReferences` 仍可先缓存引用数据，但模板仅在 `!streaming`（或本轮已 `done`）时渲染引用折叠区
- 样式保持现有引用卡片风格；收起态仅一行操作条，避免挡长答案

### 2.3 验收

- [ ] 生成过程中看不到引用区  
- [ ] 结束后出现「引用 (N)」，默认收起  
- [ ] 点展开见完整正文；可再收起  
- [ ] 刷新/切换回会话后，历史助手消息引用仍可折叠展开  

## 3. 5B 验收补齐

### 3.1 功能验收清单

| # | 项 | 期望 |
|---|----|------|
| 1 | 会话 CRUD | 创建 / 列表 / 详情 / 改名 / 删除正常 |
| 2 | 多轮追问 | 同会话能利用最近 10 条历史理解指代 |
| 3 | 持久化 | 刷新后历史与引用仍在 |
| 4 | 无命中 | user + assistant（友好提示）都落库 |
| 5 | 自动标题 | 仅默认「新会话」可被首问截断覆盖；手动改名不被覆盖 |
| 6 | 停止生成 | 中断后**只落 user、不落 assistant**（见 3.2） |

### 3.2 停止生成（文档 + 单测）

**产品约定（沿用 5B）：**

1. 请求开始后先落库 user message  
2. 前端 Abort / 连接中断 / 生成器 `GeneratorExit` 时：**不写** assistant、不写 `chat_references`  
3. 前端去掉半截助手气泡；刷新后仅见已落库的 user  

**单测要求：**

- 文件：`backend/tests/test_chat_session_api.py`（或同目录扩展）  
- 模拟流式中途中断（例如 mock `chat_stream` 在产出部分 token 后抛出 / 触发 GeneratorExit，或消费生成器至半途关闭）  
- 断言：该 `session_id` 下本轮仅有 `role=user` 的消息，**无** `role=assistant`  
- 正常成功路径、无命中路径、手动标题不被覆盖等既有用例保持通过  

**实现注意（若现状不足）：**

- 确认 `iter_session_ask_events` 在异常/中断路径不会落 assistant  
- 必要时用 `try/finally` 或明确捕获 `GeneratorExit`，避免「先拼完再写库」的窗口外误写  

### 3.3 手测建议顺序

1. 新建会话 → 提问 → 流式中确认无引用区 → 结束后展开引用  
2. 追问指代问题 → 刷新页面 → 历史与引用仍在且默认收起  
3. 停止生成 → 刷新 → 仅有用户消息  
4. 改名后再提问 → 标题不被覆盖  
5. 删会话 → 列表与消息不可再访问
